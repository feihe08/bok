# Bok 隐私政策

生效日期：2026 年 8 月 18 日
适用版本：Bok 0.0.11

Bok 是一款用于保存、关闭、整理和恢复 Chrome 标签页，并管理 Chrome 书签栏的浏览器扩展。本隐私政策说明 Bok 会处理哪些数据、为何处理，以及数据如何保存在本地。

## 1. Bok 处理的数据

当用户主动使用 Bok 保存标签页、标签组或导入 Bok JSON 数据时，Bok 可能处理以下信息：

- 标签页 URL、标题和 Chrome 提供的网站图标引用；
- Chrome 标签组的标题、颜色、标签页顺序及成员关系；
- Bok 为管理保存记录所需的本地元数据，例如创建和更新时间、分组名称、固定、锁定、归档及 Todo、Doing、Done 状态；
- 用户设置的自动归档周期、主题、默认书签目录节点 ID 和用于区分不同电脑备份的名称；
- 用户主动选择导入的 Bok JSON 文件中包含的上述数据。

当用户主动授予书签权限后，Bok 会在后台接收 Chrome 整个书签树中新建或移动节点的标题、URL 和位置变化，用于判断用户是否刚保存或移动了书签。Bok 只在书签管理和设置页面中显示或管理书签栏内容；启用备份后，后台也会读取完整书签栏以生成备份。Bok 不读取“其他书签”和“移动设备书签”的完整目录，也不会修改其中的书签。

Bok 不收集网页正文、Cookie、表单内容、密码、支付信息或 Chrome 账号凭据。

## 2. 数据用途

Bok 仅使用这些数据来提供用户可见的核心功能：

- 保存并关闭用户选择的 Chrome 标签页；
- 在本地列表中显示、搜索、整理和去重保存记录；
- 保留并恢复标签页顺序和 Chrome 标签组信息；
- 执行用户明确发起的重命名、固定、锁定、归档、任务状态、删除和导入操作；
- 在用户要求时重新打开保存的标签页或标签组。
- 显示和搜索 Chrome 书签栏，并执行用户明确发起的移动、排序、删除、文件夹归档或恢复操作；Bok 不提供手动新建、改名或修改书签 URL 的功能。
- 用户在 Chrome 中新建书签或修改新书签所在目录后，在用户配置的默认目录中创建并立即删除一个内部标记，使下一次 Chrome 原生书签保存入口默认选择该目录；未配置时沿用书签栏一级目录 `Inbox`，Bok 不会移动用户刚保存的书签。
- 书签整理按钮目前尚未启用；Bok 当前不会分析书签重复或死链，也不会自动删除或合并书签。
- 在用户选择的本机或 iCloud Drive 文件夹中，按机器名称分别保存当前电脑的 Bok 已保存网页和设置，并创建共享的 Chrome 书签栏及 Bok 书签归档备份。

Bok 不会将这些数据用于广告、用户画像、信用评估或与上述功能无关的目的。

## 3. 本地存储与传输

- 标签页 URL、标题、标签组元数据及 Bok 保存记录持久保存在当前设备 Chrome 配置文件中的 `browser.storage.local`。
- 为在浏览器运行期间关联 Bok 分组和 Chrome 标签组，Bok 会在 `browser.storage.session` 中保存短期的数字标识映射；此类会话数据不会包含网页正文。
- 当前书签栏仍由 Chrome 自身的书签存储管理，Bok 不会把它复制进 `browser.storage.local` 的标签页保存记录。用户选择的默认书签目录节点 ID 保存在 `browser.storage.local`，只对当前 Chrome 资料有效且不进入设置备份。用于重置下次默认保存目录的内部标记会立即删除，不保存在 Bok 存储中；如果用户启用了 Chrome 书签同步，这次短暂的创建和删除可能由 Chrome 同步处理。用户明确归档的文件夹会以独立的树形快照保存在 `browser.storage.local.bookmarkArchiveStore`，与标签页保存记录隔离；只有归档备份验证成功后，原文件夹才会从 Chrome 删除。
- 用户选择的备份文件夹句柄保存在扩展自己的 IndexedDB 中；机器名称、内部随机归属标识、文件夹名称、最近备份时间和错误状态保存在 `browser.storage.local`。归属标识也会写入设备归属文件，只用于阻止两台电脑意外使用同一个机器名称；周包文件名使用认领时间区分不同代次。
- Bok 已保存网页和当前设置写入机器名称对应的设备目录；Chrome 书签栏和 Bok 书签归档写入共享目录。设置备份只包含自动归档周期和主题，不包含默认书签目录节点 ID、机器名称、归属标识、权限或目录句柄。
- 主题偏好继续保存在扩展页面自己的 `localStorage` 中，并镜像到 `browser.storage.local`，供后台生成设置备份。
- 若用户选择 iCloud Drive，备份文件的后续传输与冲突处理由 macOS 和 iCloud 执行，不由 Bok 上传或控制。共享备份文件不代表 Bok 会实时同步或自动合并不同电脑的本地归档库。
- Bok 不使用 `browser.storage.sync`，不提供 Bok 云同步，也不会把保存记录上传到开发者或第三方服务器。
- Bok 0.0.11 不包含分析、广告、追踪、远程日志或死链检查功能，也不会通过网络发送用户的标签页或书签数据。

Chrome、操作系统或用户自行启用的浏览器配置文件备份行为由相应服务提供方控制，不属于 Bok 的数据传输。

Bok 不上传、不出售，也不与第三方共享标签页 URL、标题、标签组元数据或书签内容。

## 4. 出售、共享与人工访问

Bok 不出售、出租或共享用户数据。由于数据不会传输到开发者服务器，开发者及其他人员无法查看用户保存的标签页数据或 Chrome 书签。

Bok 对用户数据的使用遵循 Chrome Web Store User Data Policy 的 Limited Use 要求：数据只用于扩展的单一用途和用户可见功能，不用于个性化广告，也不用于判断信用或贷款资格。

## 5. 数据保留与用户控制

保存记录会保留在 `browser.storage.local` 中，直到用户在 Bok 中明确删除记录、清除扩展数据或卸载扩展。Bok 可能在本地保留导入前备份或无效记录的恢复副本，以防数据损坏；这些副本同样不会离开本机。导入前备份可能在后续导入时被覆盖；无效记录的恢复副本会累积，通常保留到用户清除扩展数据或卸载扩展。

用户可以在 Bok 中删除单个标签页、分组或保存记录。打开标签页或标签组本身不会删除对应的保存记录。

Chrome 书签由 Chrome 保留，直到用户通过 Bok、Chrome 或其他同步设备移动、归档或删除它们。Bok 归档会保留在 `bookmarkArchiveStore` 中，直到用户成功恢复、清除扩展数据或卸载扩展。恢复已归档文件夹时，Chrome 会重新创建内容，并可能生成新的节点 ID 和创建时间。

Chrome 书签和 Bok 书签归档的最新备份在共享目录使用固定文件名；Bok 已保存网页和设置的最新备份在各自机器名称目录使用固定文件名。重命名或重新绑定不会自动删除旧设备目录或旧代次的周包。每个认领代次只自动清理与自己的名称和代次匹配且超出保留数量的周包。清除 Bok 扩展数据或卸载 Bok 会移除扩展保存的文件夹授权、归档库、默认书签目录节点 ID、机器名称、内部归属标识和备份状态，但不会自动删除已经写入该文件夹的备份文件。

## 6. 权限

Bok 使用 Chrome 提供的 `tabs`、`tabGroups`、`storage`、`unlimitedStorage`、`favicon`、`alarms` 和 `contextMenus` 权限来完成上述本地保存、恢复、显示、定时归档和右键菜单功能。`bookmarks` 是可选权限，仅在用户主动进入书签管理、配置默认书签目录或配置书签备份时请求，用于读取、移动、删除或备份 Chrome 书签栏内容，以及通过短暂内部标记重置下一次 Chrome 原生书签保存入口的默认目录。备份文件夹由用户通过 Chrome 的文件夹选择器明确授权，不需要 Bok 读取设备上的其他文件夹。Bok 不会把这些权限用于本隐私政策未说明的目的。

## 7. 政策变更

如果 Bok 的数据处理方式发生实质变化，本政策会在新版本发布前更新，并修改生效日期。新增的数据用途不会在未披露的情况下应用于既有数据。
